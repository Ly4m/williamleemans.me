# Research: llms.txt — state of the convention as of mid-2026, and whether lmns.fr should ship one

Date: 2026-07-19. All sources accessed 2026-07-19. Primary sources fetched directly where possible; secondary reporting is flagged as such.

## TL;DR — **SKIP** (revisit if a major AI vendor announces support)

**Recommendation: do not ship an llms.txt for lmns.fr today.**

Reasoning, cost vs. realistic benefit:

- **No major AI vendor honors it.** As of mid-2026, none of OpenAI, Anthropic, Google, Perplexity, Microsoft, or Mistral documents any consumption of llms.txt. Google has *explicitly* stated it does not and will not use it ([Gary Illyes, July 2025](https://searchengineland.com/google-says-normal-seo-works-for-ranking-in-ai-overviews-and-llms-txt-wont-be-used-459422); [Google Search Central docs](https://developers.google.com/search/docs/appearance/ai-features)). Every other vendor's crawler documentation points site owners to robots.txt and says nothing about llms.txt.
- **Server logs confirm nobody fetches it.** Ahrefs' study of 137,000 domains found **97% of llms.txt files received zero requests in May 2026** — from any bot or human ([Ahrefs, June 2026](https://ahrefs.com/blog/llmstxt-study/)).
- **This site has nothing to gain.** lmns.fr is a fully server-rendered static Astro site; GPTBot, ClaudeBot and PerplexityBot already read the HTML fine (per the site's own crawlability audit). llms.txt's stated purpose is to help LLMs bypass "complex HTML, ads, or JavaScript" ([llmstxt.org](https://llmstxt.org)) — a problem this site does not have. Six clean articles plus an RSS feed ([/rss.xml](https://lmns.fr/rss.xml)) and a sitemap already give machines a structured index.
- **The one real, confirmed consumer** of llms.txt is developer tooling (Claude Code, Cursor, etc.) fetching *API/product documentation* indexes — a use case that does not apply to a 6-article personal blog.
- **Cost is small but not zero:** a file to keep in sync with the blog collection by hand (or a build script to write and maintain), for a benefit for which the evidence is currently zero.

If a major vendor (OpenAI, Anthropic, Google, Perplexity) ever publishes first-party documentation saying its crawlers request `/llms.txt`, this decision should be revisited — the file takes ten minutes to add (a draft is in the appendix below).

## 1. What the spec says

Source: [llmstxt.org](https://llmstxt.org) — proposal by Jeremy Howard (Answer.AI), published 2024-09-03. Fetched 2026-07-19.

- A Markdown file served at the site root: `/llms.txt`. Purpose: give LLMs a concise, curated map of the site's content that fits in a context window at **inference time** (explicitly positioned as complementary to `robots.txt` (training/crawling control) and `sitemap.xml` (exhaustive index)).
- Required/optional structure, in order:
  1. **H1** with the site/project name — *the only required section*;
  2. a **blockquote** with a short summary;
  3. optional free-form Markdown paragraphs with details;
  4. zero or more **H2-delimited "file lists"**: Markdown lists where each item is "a required markdown hyperlink `[name](url)`, then optionally a `:` and notes";
  5. an H2 section literally named **`Optional`** whose links can be skipped when a shorter context is needed.
- The spec also suggests serving **`.md` twins of HTML pages** (same URL + `.md`) and describes tooling (`llms_txt2ctx`) that expands llms.txt into `llms-ctx.txt` / `llms-ctx-full.txt`. The widely-shipped variant **`llms-full.txt`** (entire content inlined into one file) comes from ecosystem practice (notably Mintlify), not from the core spec's required format.
- The spec does not mandate a language; files in the wild are overwhelmingly English, but for a French-content site there is no spec-level reason not to write the notes in French — the linked content is French either way.

## 2. Who actually honors it as of mid-2026 (per vendor)

The essential distinction: **(a)** vendors whose *crawlers/answers consume* llms.txt, **(b)** vendors that merely *publish* an llms.txt for their own docs (producer, not consumer), and **(c)** tool vendors that *generate* llms.txt for customers. Only (a) would create value for lmns.fr — and category (a) is **empty**.

### Confirmed NEGATIVE (first-party, on record)

- **Google** — Gary Illyes at the Search Central Deep Dive APAC event, 2025-07-23: Google does not support llms.txt and is not planning to (reported by [Search Engine Land, July 2025](https://searchengineland.com/google-says-normal-seo-works-for-ranking-in-ai-overviews-and-llms-txt-wont-be-used-459422) — secondary report of a first-party statement). Google's own ["AI features and your website" doc](https://developers.google.com/search/docs/appearance/ai-features) (fetched 2026-07-19) never mentions llms.txt and states verbatim: *"You don't need to create new machine readable files, AI text files, or markup to appear in these features."* John Mueller (Reddit, 2025, via [Search Engine Journal](https://www.searchenginejournal.com/google-says-llms-txt-comparable-to-keywords-meta-tag/544804/)): *"AFAIK none of the AI services have said they're using LLMs.TXT (and you can tell when you look at your server logs that they don't even check for it). To me, it's comparable to the keywords meta tag."*

### No documented support (absence of any first-party commitment)

- **OpenAI (GPTBot / OAI-SearchBot / ChatGPT-User)** — the official crawler documentation ([platform.openai.com/docs/bots](https://platform.openai.com/docs/bots)) documents robots.txt control and published IP ranges; llms.txt appears nowhere in it. OpenAI *publishes* an llms.txt for its own API docs (category (b), Mintlify-generated) — that is not evidence its crawlers read yours.
- **Anthropic (ClaudeBot / Claude-User / Claude-SearchBot)** — the official crawler doc ([support.claude.com, updated ~2026-02-20](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler)) describes three bots, all controlled via robots.txt (incl. `Crawl-delay`); no mention of llms.txt. Anthropic publishes an llms.txt for docs.claude.com (category (b)). Separately, **Claude Code** the *dev tool* does fetch llms.txt when pointed at documentation sites — it was the #2 named fetcher in Ahrefs' log data — but that is agent tooling reading docs indexes, not ClaudeBot crawling blogs.
- **Perplexity (PerplexityBot / Perplexity-User)** — official crawler docs ([docs.perplexity.ai](https://docs.perplexity.ai/docs/resources/perplexity-crawlers)) document robots.txt compliance and IP verification; no llms.txt consumption documented. Perplexity publishes its own [docs llms-full.txt](https://docs.perplexity.ai/llms-full.txt) (category (b)).
- **Microsoft / Bing / Copilot** — no published support for llms.txt in any Bing or Copilot documentation as of mid-2026 (surveyed via [nohacks.co AI user-agent reference, 2026](https://nohacks.co/blog/ai-user-agents-landscape-2026) and vendor doc searches; no first-party positive statement exists to cite).
- **Mistral (MistralAI-User)** — documented as a user-triggered fetcher; no llms.txt statement ([nohacks.co reference, 2026](https://nohacks.co/blog/ai-user-agents-landscape-2026)).

### Confirmed adopters — but in the wrong categories for this site

- **Category (b), producers:** Anthropic, OpenAI, Stripe, Cloudflare, Perplexity publish llms.txt for their *developer docs*.
- **Category (c), generators:** Mintlify auto-generates `/llms.txt`, `/llms-full.txt` and `.md` page twins for every docs site it hosts, since November 2024 ([mintlify.com/docs/ai/llmstxt](https://www.mintlify.com/docs/ai/llmstxt); [launch post](https://www.mintlify.com/blog/simplifying-docs-with-llms-txt)) — this single rollout accounts for a large share of all llms.txt files in existence.
- **Genuine consumers:** coding agents/IDEs (Claude Code, Cursor, Windsurf, Cline, Aider) fetch `/llms.txt` when a user points them at a documentation site ([nohacks.co, 2026](https://nohacks.co/blog/ai-user-agents-landscape-2026); corroborated by Claude-Code ranking #2 among named fetchers in [Ahrefs' logs](https://ahrefs.com/blog/llmstxt-study/)). Relevant for API docs; irrelevant for a personal blog.

### Server-log evidence (do crawlers request /llms.txt in practice?)

- **Ahrefs** (Ryan Law et al.), server logs of **137,000 domains**, published June 2026 ([ahrefs.com/blog/llmstxt-study](https://ahrefs.com/blog/llmstxt-study/)): ~38,000 of those domains had a valid llms.txt; **97% of those files got zero requests in May 2026**. Of the rare fetches, 19.5% came from named AI tools (GPTBot first, Claude-Code second) and ~12% from the GEO/SEO industry studying itself. Ahrefs' conclusion: no evidence llms.txt improves AI retrieval, traffic, or accuracy.
- **Otterly.AI**, 90-day AI-bot monitoring (2026): 62,100 AI bot visits recorded, **84** (0.1%) targeted llms.txt (reported via [ppc.land, 2026-07-02](https://ppc.land/llms-txt-adoption-rises-8-8x-but-97-of-files-get-zero-ai-requests/) — secondary).
- Breakdown of *who* does request the files, same ppc.land roundup: SEO audit tools 21.7%, unidentified bots 14.9%, generic crawlers 13.1%; GPTBot 4.51%, ClaudeBot 0.80% — i.e., the file's main audience today is the SEO tooling industry, not AI answer engines.

## 3. Prevalence

Counts vary wildly with methodology and sample; all agree it is a docs-site phenomenon, not a blog phenomenon:

- **Originality.ai** tracking (~3M sites monitored, June 2025 → May 2026): llms.txt instances grew **4,088 → 36,120** (8.8x); ~39,000 including `llms-full.txt`/`ai.txt` variants. ~39.6% of found files are auto-generated plugin stubs. Report 2026-07-02, via [ppc.land](https://ppc.land/llms-txt-adoption-rises-8-8x-but-97-of-files-get-zero-ai-requests/).
- **Ahrefs** (137k domains, Ahrefs-customer sample, so skewed toward SEO-aware sites): 28% publish one ([Ahrefs, June 2026](https://ahrefs.com/blog/llmstxt-study/)).
- **SE Ranking** (300,000-domain study, mid-2026): 10.13% adoption ([via search reporting, 2026](https://ai.aeo.press/the-state-of-llms-txt-in-2026) — secondary).
- **BuiltWith** claimed 844,000+ sites as of 2025-10-25 (via [getpublii.com guide](https://getpublii.com/blog/llms-txt-complete-guide.html) — secondary; the count includes WordPress-plugin auto-stubs, which explains the gap vs. Originality.ai).
- Community directories: [llms-text.com/directory](https://llms-text.com/directory) lists ~788 verified sites; [llmstxt.site](https://llmstxt.site) and [directory.llmstxt.cloud](https://directory.llmstxt.cloud) list hundreds — dominated by API/developer-docs sites (the Mintlify effect), with personal blogs a rarity.

## 4. Cost/benefit for lmns.fr specifically

- The site is static, server-rendered Astro; there is no JS wall between crawlers and content. The audit already established GPTBot/ClaudeBot/PerplexityBot read the HTML fine. The problem llms.txt solves does not exist here.
- Machine-readable indexes already exist: `sitemap-index.xml` (declared in [public/robots.txt](../../public/robots.txt)) and the RSS feed with full metadata.
- Six articles ≈ maybe 30 lines of llms.txt. Trivial to write — but also trivially redundant with the sitemap/RSS, and one more thing that silently drifts out of date with each new post unless generated at build time (an Astro endpoint `src/pages/llms.txt.ts` could generate it from the content collection — but that's build machinery in exchange for a file with a 97% chance of never being fetched).
- The spec's companion recommendation (`.md` twins of every page) would require extra Astro endpoints per route for, again, no documented consumer.

**Verdict: SKIP.** Plainly: the evidence for vendor adoption is not "weak", it is absent-to-negative, and the only confirmed consumers (coding agents reading API docs) will never point at a personal French blog.

## Appendix — draft llms.txt, if the decision is ever reversed

Placement in this repo: `public/llms.txt` (Astro copies `public/` verbatim to the site root → served at `https://lmns.fr/llms.txt`). Better: generate it from the blog collection via `src/pages/llms.txt.ts` so it never drifts. Language: the spec is language-agnostic; since the content is French and consumers are LLMs, French descriptions are fine — noting `lang: fr` in the summary helps.

```markdown
# William Leemans — lmns.fr

> Blog technique personnel de William Leemans, développeur. Articles en français
> (lang: fr) sur le développement web, Git, les systèmes distribués et la
> construction de ce site (Astro, Svelte, Canvas).

## Blog

- [Comprendre PACELC](https://lmns.fr/blog/cap-pacelc-system-design): CAP, PACELC, cohérence, latence — les compromis des systèmes distribués (2026-05-02)
- [Les flux RSS](https://lmns.fr/blog/flux-rss): ajouter un abonnement RSS simple à un site statique (2026-01-20)
- [Animation de particules](https://lmns.fr/blog/animation-de-particules): une animation Canvas pour le fond du site (2025-11-06)
- [Garder un historique Git propre](https://lmns.fr/blog/garder-un-historique-git-propre): bons commits et usage efficace de rebase (2025-10-15)
- [Nouvelle Machine](https://lmns.fr/blog/nouvelle-machine): reconstruction d'un environnement de dev sur MacBook Pro 14″ (2025-09-23)
- [Hello World](https://lmns.fr/blog/hello-world): la création de ce site (2025-08-11)

## Optional

- [Now](https://lmns.fr/now): ce que je fais en ce moment

```
